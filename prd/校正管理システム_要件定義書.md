# 計量校正管理システム — 要件定義書

## 1. プロジェクト概要

### 1.1 背景
精密機器メーカーでは、製造ラインで使用する測定機器（ノギス、マイクロメータ、圧力計、温度計、天秤など）の定期的な校正が品質管理の根幹を担っている。現在、多くの現場では校正スケジュール管理を Excel で行い、校正記録は紙の証明書として保管されている。

### 1.2 課題
- 校正期限の管理が属人化しており、期限切れの機器がラインに残留するリスクがある
- 校正記録の検索性が低く、トレーサビリティの確保に時間がかかる（品質マネジメント関連規格の監査対応）
- 測定不確かさ（Measurement Uncertainty）の評価が手計算で、計算ミスが発生しやすい
- 複数拠点（京都本社 / 東京ラボ / 大阪工場）の校正データを一元管理できていない

### 1.3 目標
校正スケジュール、校正記録、測定不確かさ評価を Web アプリケーションで一元管理し、校正機関に求められる国際規格に準拠したトレーサビリティを確保する。

## 2. ターゲットユーザー
- **計測管理担当者**：校正スケジュールの管理、校正作業の実施と記録
- **品質保証部門**：監査対応、トレーサビリティ確認、レポート出力
- **現場オペレーター**：機器の使用可否確認（校正済みかどうか）

## 3. 機能要件

### 3.1 機器マスタ管理
- 機器の登録（機器ID、名称、型式、シリアル番号、製造元、測定範囲、分解能）
- 機器カテゴリ分類（長さ / 質量 / 温度 / 圧力 / 電気 / 体積）
- 所属拠点・部署・保管場所の管理
- 機器ステータス（使用中 / 校正中 / 保管中 / 廃棄）

### 3.2 校正スケジュール管理
- 校正周期の設定（機器ごと、またはカテゴリごと）
- 次回校正日の自動算出とアラート通知（期限前 30 日 / 7 日 / 1 日）
- 校正作業の計画立案と担当者割り当て
- 校正実績の登録と次回スケジュール自動更新

### 3.3 校正記録・証明書
- 校正記録の入力（基準器情報、環境条件、測定値、合否判定）
- 校正証明書の自動生成（PDF）
- 校正履歴の時系列表示とエクスポート（CSV / PDF）

### 3.4 測定不確かさ評価
- 不確かさ予算（Uncertainty Budget）の自動計算
  - A 評価（統計的手法：繰り返し測定の標準偏差）
  - B 評価（その他の情報：校正証明書、仕様書からの推定）
- 合成標準不確かさ uc(y) の計算
- 拡張不確かさ U = k × uc(y)（包含係数 k=2、信頼水準 約 95%）
- 不確かさ評価レポートの出力

### 3.5 ダッシュボード・レポート
- 校正進捗ダッシュボード（今月 / 来月の校正予定、遅延機器数）
- 機器カテゴリ別 / 拠点別の校正状況レポート
- 監査対応用トレーサビリティレポート

## 4. 非機能要件
- **可用性**：99.5%（平日 8:00-20:00 JST の利用が主）
- **セキュリティ**：SSO 対応（Azure AD / Google Workspace）、役割ベースアクセス制御（RBAC）
- **データ保全**：校正記録の改ざん防止（監査ログ）、バックアップ日次取得
- **多言語**：日本語 UI を基本、英語 UI 切り替え可能
- **パフォーマンス**：ダッシュボード表示 2 秒以内、校正記録検索 3 秒以内

## 5. 技術制約
- バックエンド：Python（FastAPI）+ SQLite（POC 段階）
- フロントエンド：React + TypeScript
- 認証：JWT ベース、SSO 連携は Phase 2 で対応
- ホスティング：社内オンプレまたは VPC 内（データ外部持ち出し不可）

## 6. 用語集
| 用語 | 説明 |
|------|------|
| 校正（Calibration） | 測定器の示す値と標準値との関係を確定する作業 |
| トレーサビリティ | 測定結果が国家標準または国際標準に辿れる性質 |
| 測定不確かさ | 測定結果に付随する、真の値が存在すると推定される範囲 |
| 包含係数 k | 拡張不確かさを求めるための乗数（通常 k=2） |
| 基準器 | 校正に用いる、より高精度な測定器 |
